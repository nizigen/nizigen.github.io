PYTHON

随着程序越来越长，有必要遵循一些代码格式约定，让所有人写出的代码结构大致一致。PEP 8（Python Enhancement Proposal）是最古老的 PEP 之一，向 Python 程序员提供了代码格式指南：https://python.org/dev/peps/pep-0008/

源文件编码

Python 3 的源码文件使用 UTF-8 编码（Python 2 默认是 ASCII）。编辑器和 IDE 里也要统一设置为 UTF-8，设置方法见 开发环境搭建。

缩进

每级缩进使用 4 个空格，既提高可读性，又给多级缩进留下足够空间。不要混用制表符和空格，建议把编辑器设置为按 Tab 键时插入空格。缩进的语法规则和报错见 缩进。

导入

每个 import 语句只导入一个模块，尽量避免一次导入多个模块。

# 推荐
import os
import sys

# 不推荐
import os, sys

分号

不要在行尾添加分号，也不要用分号把两条命令放在同一行。虽然语法上允许，但并不是所有情况都可以，所以不推荐：

num = 6;  # 不要这样写
if num % 2 == 0:print("偶数"); print("双数")  # 不要这样写

行长

建议每行不超过 79 个字符，注释和文档字符串不超过 72 个字符。最初制定这一指南时，大多数终端窗口每行只能容纳 79 个字符；现在屏幕宽得多，但专业程序员常在一屏里并排打开两三个文件，标准行长可以让他们同时看到各个文件的完整行。有些工具自动生成文档时还会在每行注释开头添加格式化字符，这也是 72 的由来。

这条指南并非不可逾越，有些团队把最大行长设为 99。在大多数编辑器中都可以设置一条竖线作为视觉标志。学习阶段不必过度在意，但协作开发时大家几乎都遵守 PEP 8。

行太长时，建议用小括号把多行内容隐式连接起来，而不推荐用反斜杠 \ 连接：

s = ("C语言中文网是中国领先的C语言程序设计专业网站，"
     "提供C语言入门经典教程、C语言编译器、C语言函数手册等。")
print(s)

C语言中文网是中国领先的C语言程序设计专业网站，提供C语言入门经典教程、C语言编译器、C语言函数手册等。

此规范适用于绝大多数情况，但以下 2 种情况除外：

  • 导入模块的语句过长。
  • 注释里的 URL。

空行

使用空行把程序的不同部分分开，但不要滥用。例如 5 行创建列表的代码和 3 行处理列表的代码之间，空一行就合适，不要空三四行。

通常在顶级定义（函数或类的定义）之间空两行，方法定义之间空一行，其他需要分隔功能的位置也可以空一行。

空行不影响代码运行，但影响可读性：Python 解释器根据水平缩进来解读代码，不关心垂直间距。

空格

通常在运算符两侧、函数参数之间以及逗号两侧，都建议使用空格分隔。

total = a + b          # 运算符两侧加空格
print(a, b)            # 逗号后加空格
result = func(x, y)    # 参数之间加空格

不要以空格结束一行代码。行末的空格不可见，却可能闹出问题，比如反斜杠续行符后面如果再接空白字符，就不能再当作续行符使用。很多编辑器可以设置自动去除行尾空格。

命名

模块、包、类、函数、常量的命名风格见 标识符与命名。函数名使用 snake_case，不使用小驼峰。
