看板娘现在用的是从《无期迷途》客户端里直接解包出来的模型和原始动作，不是手搓的。 这里记录动作清单，以及每个动作在游戏里和在本博客上分别是怎么触发的。

一、模型和动作从哪来

游戏版本 2.4.67.0（2026-10），资源位置：

内容资源
模型 moc3assets/art_live2d_characters_shalom_N.bundle
贴图 + metaassets/art_live2d_characters_shalom_N_shalom_N.4096.bundle
动作 .fadeassets/art_live2d_characters_shalom_N_motion.bundle
时间轴 AnimationClipassets/art_live2d_characters_shalom_N_animation.bundle

解包 → 转 motion3.json → 放进 live2d_api 的 model/5732/Shalom_N/。 转换细节见另一篇《如何在博客里用你自己的 Live2D 模型》。

四套模型（Shalom_2 ~ Shalom_5），动作数量不一样：

模型动作数说明
Shalom_29黑西装、审判席
Shalom_310红丝绒、夜花如昼
Shalom_410深蓝星空、红裙（最精细，574 个参数）
Shalom_53水墨兰亭（兰亭月会）

二、动作清单

动作名就是游戏里的事件名，motion3.json 里的 Meta.Loop 只有 Idle 是 true（无限循环）， 其余都是一次性播放完就回到待机。

动作游戏里的触发博客上的触发是否循环
Idle待机，一直循环加载完成、以及任何动作播完后自动接上✅
Greet登场 / 打招呼切换模型、刷新页面时先播一次❌
Click_Head点头部点画面上方 30%❌
Click_Body / Click_Body1 / Click_Body2点身体点画面中部❌
Click_Hand / Click_HandLeft / Click_HandRight点手点画面中部（优先于身体）❌
Click_Leg点腿点画面下方 28%❌
Boring长时间不操作60 秒没有任何点击❌
Background切场景 / 背景演出不自动播，留着手动调❌
Level升级 / 突破不自动播❌
Drag_End_2拖拽结束时不自动播（博客里没做拖拽）❌

几点说明：

  • 游戏里点头部、点手、点腿是三条不同的动作，所以按点击位置分区触发，尽量还原这个手感。
  • Shalom_5 只有 Idle / Click_Body / Background 三个动作，点哪都会落到 Click_Body。
  • Shalom_4 的手部动作分左右手（Click_HandLeft / Click_HandRight），中间的点击区优先用它。
  • 动作播完会自动淡回 Idle，淡入淡出 0.4 秒（Idle 是 1 秒）。

三、触发是这么实现的

看板娘脚本是 /js/shalom-live2d.js，核心逻辑：

// 待机
model.motion("Idle");

// 点击分区：按点击位置在画布上的纵向比例决定播哪个
const y = (ev.clientY - rect.top) / rect.height;
if (y < 0.30)      model.motion("Click_Head");
else if (y < 0.72) model.motion("Click_Hand");   // 没有就退到 Click_Body
else               model.motion("Click_Leg");

// 一次性动作播放结束后回到 Idle
model.motion(name).then(idle, idle);

model.motion() 返回的 Promise 在动作播完时 resolve，所以不用自己算时长。

另外两个细节：

  • model3.json 里写了 Groups.EyeBlink = [ParamEyeLOpen, ParamEyeROpen]，所以不播动作时也会自然眨眼。
  • 动作按 Idle / TapBody 两组额外聚合了一份，方便 live2d-widget 那类只认这两个组名的播放器直接用。

四、换装和参数

右上角 ↻ 在四套模型之间循环切换（Shalom_5 → 4 → 3 → 2），× 收起。 窗口宽度小于 900px 时整个看板娘不加载，避免挡住手机端正文。

如果只想换个默认模型，改 MODELS 数组第一项就行：

var MODELS = ["Shalom_4", "Shalom_5", "Shalom_3", "Shalom_2"];

五、已知问题

  • Shalom_4 的模型里有一块很浅的 Mask 平面，在深色主题下会看到一块浅色矩形。 这是模型自带的遮罩层，暂时没处理。
  • 动作是从 Unity 的 .fade 反推成 motion3.json 的，极少数纯阶梯/线性关键帧可能和游戏里差一点点。
  • 物理（头发、衣摆摆动）没有解出来，游戏里那部分挂在 prefab 的匿名组件上，导出流程没覆盖。
