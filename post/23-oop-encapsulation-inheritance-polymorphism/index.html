封装、继承、多态是面向对象的三大特征。类与对象的语法见 类与对象，这一篇讲三者各自的实现方式，以及把它们串起来的 MRO。

封装

封装的目的与 Java 完全一致，只有实现方式不同：

  1. 隐藏内部实现——把数据和操作数据的方法绑在一起，外部不必知道内部如何存储和处理；
  2. 保证数据安全——限制外部随意修改，通过统一接口做校验、日志、联动更新；
  3. 降低耦合——外部只依赖暴露的接口，内部实现变了，只要接口不变就不用改外部代码。

Java 把「私有化属性」当作实现封装的唯一常规手段，于是有了「私有化 = 封装」的印象；Python 提供了多种更灵活的方式，私有化只是其中一种，而且不是最常用的。

约定式封装：单下划线 _attr

属性或方法以单个下划线开头（self._age、def _calc_score(self)），向其他开发者传递信号：这是内部实现，外部不要直接访问。Python 不会做任何语法限制，PyCharm 等检查工具会对外部访问给出提示，靠的是约定。下划线含义的完整规则见 标识符与命名。

class Student:
    def __init__(self, math, english):
        self.math = math
        self.english = english
        self._total = math + english  # 内部属性，外部无需关注

    # 内部实现：单下划线标识，外部不要调用
    def _calc_average(self):
        return self._total / 2

    # 外部接口：公开方法，供外部调用
    def get_average(self):
        return self._calc_average()


s = Student(90, 80)
print(s.get_average())  # 正确用法
print(s._total)         # 语法上能跑，PyCharm 会警告
print(s._calc_average())  # 语法上能跑，PyCharm 会警告

接口式封装：@property

这是替代 Java getter/setter 的方案，目标是「给属性加逻辑，同时保持 对象.属性 这种简洁接口」（@property 本身是装饰器的应用，见 装饰器）：

  • 用 @property 标记一个返回属性值的方法，称为 getter；
  • 用 @getter方法名.setter 标记一个设置属性值的方法，称为 setter；
  • 封装对调用方完全透明，以后给原本公开的属性加上校验，外部代码不用改；
  • @property 装饰的方法名不要和实例属性重名，否则无限递归。

原来没有校验的 Person：

class Person:
    def __init__(self, name=None, age=None):
        self.name = name
        self.age = age

改成接口式封装后，外部的访问方式一个字都不用变：

class Person:
    def __init__(self, name=None, age=None):
        self.name = name
        self.__age = age

    @property
    def age(self):
        return self.__age

    @age.setter
    def age(self, age):
        if age < 0 or age > 100:
            raise ValueError("年龄超出范围")
        self.__age = age


p = Person("张三", 18)
print(f"姓名：{p.name},年龄：{p.age}")
p.name = "张三丰"
p.age = 23
print(f"姓名：{p.name},年龄：{p.age}")

try:
    p.age = 200
except ValueError as e:
    print("p.age = 200 ->", e)

姓名：张三丰,年龄：23
p.age = 200 -> 年龄超出范围

Warning

上面 __init__ 里写的是 self.__age = age，它==绕过了 setter==，非法值照样进对象：实测 Person("李四", 200).age 输出 200，没有被拦截。把这一行改成 self.age = age 才会走校验逻辑。

Warning

名字撞车就是死循环：getter 里写 return self.age、setter 里写 self.age = age，都会再次触发属性本身：

名称改写式封装：双下划线 __attr

Python 没有 private 关键字，双下划线是唯一的语法级封装手段，也是语法上最接近「私有化」的写法。但它的本质是名称改写（name mangling），不是真正的私有。

  • 定义 __secret 时，Python 在编译期把它改写成 _类名__secret；
  • 外部写 对象.__secret 或 类名.__secret 会抛 AttributeError，但用改写后的名字 对象._类名__secret 仍能访问；
  • __方法 同理。
class Person:
    """人的类"""
    __home = "earth"  # 私有类属性

    def __init__(self, name, age=0):
        self.__name = name  # 私有实例属性
        if self.__check_age(age):
            self.__age = age  # 私有实例属性

    def __check_age(self, age):  # 私有方法
        if age < 0 or age > 100:
            raise ValueError("年龄超出范围")
        return True

    def __str__(self):
        return f"姓名：{self.__name}，年龄：{self.__age}"


p = Person("张三", 18)
print(p)

try:
    print(p.__name)
except AttributeError as e:
    print("p.__name ->", e)

try:
    print(Person.__home)
except AttributeError as e:
    print("Person.__home ->", e)

print(f"Person.__home = {Person._Person__home}")
print(f"p.__name = {p._Person__name}")
print(f"p.__age = {p._Person__age}")
print(p._Person__check_age(20))

try:
    Person("李四", -18)
except ValueError as e:
    print("Person('李四', -18) ->", e)

注意 p.__name 报错是因为在类体之外不做改写，而 p._Person__name 直接命中改写后的名字。日常封装极少用这种方式，原因有三：

  1. 用改写后的名字照样能访问，挡不住有心人；
  2. 写法繁琐，破坏 Python 的简洁，违背「约定优于强制」的设计哲学；
  3. 只在继承场景中、需要防止子类意外覆盖父类内部属性时偶尔使用。

第三种场景长这样——父子类各有一个 __info，改写后是两个不同的属性，互不覆盖：

class Parent:
    def __init__(self):
        self.__info = "父类的内部信息"  # 改写为 _Parent__info


class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__info = "子类的信息"  # 改写为 _Child__info


p = Parent()
c = Child()

print(p._Parent__info)   # 父类的内部信息
print(c._Child__info)    # 子类的信息
print(c._Parent__info)   # 父类的内部信息

_ 与 __ 怎么选

单下划线 _name（约定私有）双下划线 __name（名称改写）
类的内部成员，希望子类能继承/修改，但不希望外部业务代码随意访问类的核心成员，绝对不希望子类重写/修改，避免命名冲突
模块内的变量与函数，只希望在模块内部使用，不希望被 import * 导入敏感成员（密码、核心配置），需要语言层面的保护
临时的、辅助性的成员，开发调试时需要方便访问框架/库的底层类，需要严格封装，避免使用者改内部逻辑

最小封装原则

Python 的「伪私有」本质是：==没有真正不可突破的私有==——双下划线的 __name 也能用 _类名__name 绕过去，和 Java/C++ 的 private 有本质区别。

Python 的设计哲学里有一句经典的话：“We are all consenting adults here”（我们都是成年人），意思是 Python 不强制限制开发者做什么，更倾向于「约定优于强制」。私有设计的思路是阻止粗心的错误，而非阻止恶意的破坏：无论单下划线的约定私有，还是双下划线的名称改写，都是为了规范协作，而不是限制操作。

社区对封装的理解可以总结成一句话：==能不封装就不封装，需要封装时极简封装==，这和 Java「所有属性都要封装」形成鲜明对比。具体落地规则：

  1. 简单属性（无校验、无逻辑、无内部关联）：直接公开，不用 _ 也不用 property，比如 self.name、self.gender；
  2. 类内自用的属性/方法（外部无需关注）：用单下划线 _attr 做约定式封装；
  3. 需要数据校验、日志、联动逻辑的属性：用 property 做接口式封装；
  4. 继承场景中防止子类覆盖：才考虑双下划线 __attr。

核心是避免过度封装：封装是为了让代码更安全、更容易维护，不是为封装而封装，Python 拒绝为「形式上的封装」写繁琐的代码。

继承

Python 中没有显式指定父类的类，默认继承自 object，它是所有类的根类（顶级父类）。

继承的目的是让子类（派生类）复用父类（基类/超类）的属性和方法，同时可以扩展、重写父类的内容。它的前提是 is-a 关系：狗是一种动物 → Dog 继承 Animal；学生是一种人 → Student 继承 Person；矩形是一种图形 → Rectangle 继承 Shape。

优点缺点
代码复用：父类的通用逻辑只写一次耦合度高：父类一改，所有子类都受影响
功能扩展：新增/重写方法即可，符合开闭原则多继承复杂：MRO、菱形继承增加理解成本
结构清晰：类之间的层级关系一目了然灵活性低：继承关系在定义时就固定了

单继承与 super()

class 子类名(父类名):
    子类体

__init__ 的调用规则：

  1. 子类没有重写 __init__，实例化子类时自动调用父类的 __init__；
  2. 子类重写了 __init__，只执行子类的，父类的不会自动执行，需要用 super().__init__(...) 手动调用，否则父类的初始化逻辑会丢失。
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f"{self.name}吃东西....")


class Student(Person):
    def __init__(self, name, age, score):
        super().__init__(name, age)
        self.score = score

    def study(self):
        print(f"{self.name}在学习，年龄为{self.age}，得分为{self.score}")


class Teacher(Person):
    def __init__(self, name, age, major):
        super().__init__(name, age)
        self.major = major

    def teach(self):
        print(f"{self.name}老师，年龄为{self.age}，主攻{self.major}")


class Doctor(Person):
    def work(self):
        print(f"{self.name}医生，年龄为{self.age}")


s = Student("张三", 18, 90)
s.eat()
s.study()

t = Teacher("李四", 28, "Python")
t.eat()
t.teach()

d = Doctor("王五", 38)
d.eat()
d.work()

属性覆盖

父类的同名类属性不会被覆盖，父类非 __ 私有的同名实例属性会被覆盖：

  • 父子类同名属性逻辑意义相同时，父类声明过，子类不必重新定义；
  • 逻辑意义不同时，应该用不同的名字区分；
  • 绝不允许子类覆盖的属性，用 __attr 私有化。
class Parent:
    # 类属性
    a = 10
    _b = 10
    __c = 10

    def __init__(self):
        # 实例属性
        self.x = 10
        self._y = 10
        self.__z = 10


class Child(Parent):
    a = 20    # 语法允许，但不建议
    _b = 20
    __c = 20

    def __init__(self):
        super().__init__()
        # self.x = 20   # 会覆盖父类的实例属性 x
        # self._y = 20  # 会覆盖父类的实例属性 _y
        self.__z = 20   # 不会覆盖父类的 __z（父类的已被改写为 _Parent__z）

    def show(self):
        print("父子类的类属性：")
        print(f"父类的a={Parent.a},子类a={Child.a}")
        print(f"父类的_b={Parent._b},子类_b={Child._b}")
        print(f"父类的__c={Parent._Parent__c},子类__c={Child._Child__c}")
        print("父子类的实例属性：")
        print(f"x={self.x}")
        print(f"_y={self._y}")
        print(f"__z={self.__z}")
        print(f"_Parent__z={self._Parent__z}")


c = Child()
c.show()

父子类的类属性：
父类的a=10,子类a=20
父类的_b=10,子类_b=20
父类的__c=10,子类__c=20
父子类的实例属性：

_y=10

同名类属性各自独立（Parent.a 与 Child.a 都还在）；实例属性 x、_y 由父类初始化，子类没动，所以是 10；self.__z 在子类里是 _Child__z，父类的 _Parent__z 也留着，两者并存。

重写父类的方法

方法名相同即重写。Python 没有方法重载，同名方法后定义的会覆盖先定义的。

重写实例方法时，可以用 super().方法名() 调用父类的实现（用 父类名.方法名(self) 效果相同）：

class Flyable:
    """飞行能力类：使用此类的子类需要提供 name 属性"""

    def fly(self):
        print(f"{self.name} 正在飞行")


class Bird:
    """鸟类基类"""

    def __init__(self, name):
        self.name = name

    def make_sound(self):
        print(f"{self.name} 在鸣叫")

    def eat(self):
        print(f"{self.name}吃东西....")


class Duck(Bird, Flyable):
    """鸭子类 - 继承鸟类和飞行能力"""

    def __init__(self, name, price):
        super().__init__(name)
        self.price = price

    def catch_fish(self):        # 新增方法
        print(f"{self.name} 抓 fish")

    def make_sound(self):        # 重写 Bird 的 make_sound
        print(f"{self.name} 嘎嘎嘎")

    def eat(self, food):         # 重写 Bird 的 eat，形参列表可以不同
        print(f"{self.name} 吃{food}....")

    def fly(self):               # 重写 Flyable 的 fly
        super().fly()
        print(f"{self.name} 飞也飞不高")


duck = Duck("小黄鸭", 10)
duck.catch_fish()
duck.make_sound()
duck.eat("虫子")
duck.fly()

重写类方法和静态方法时，调用父类实现的方式有区别：

  • 父类名.类方法()：父类方法收到的 cls 是父类（推荐）；
  • 父类名.静态方法()：没有 cls 参数（推荐）；
  • super().类方法()：父类方法收到的 cls 是子类（可以，但不推荐）；
  • super().静态方法()：不支持——静态方法里没有 self/cls，无参 super() 拿不到参数，实测抛 RuntimeError: super(): no arguments；绕法是 super(子类, 子类).静态方法()，但没有必要。
class Bird:
    info = "鸟类"

    @classmethod
    def print_info(cls):
        print(f"Bird类.print_info，cls类名是{cls.__name__},{cls.info=},{Bird.info=}")

    @staticmethod
    def show():
        print(f"Bird类.show,{Bird.info=}")


class Duck(Bird):
    info = "鸭子"

    @classmethod
    def print_info(cls):
        super().print_info()      # 此处父类方法的 cls 是 Duck
        # Bird.print_info()       # 换成这种写法，父类方法的 cls 就是 Bird
        print(f"Duck类.print_info，cls类名是{cls.__name__},{cls.info=},{Duck.info=}")

    @staticmethod
    def show():
        Bird.show()
        print(f"Duck类.show,{Duck.info=}")


Duck.print_info()
Duck.show()

Bird类.print_info，cls类名是Duck,cls.info='鸭子',Bird.info='鸟类'
Duck类.print_info，cls类名是Duck,cls.info='鸭子',Duck.info='鸭子'
Bird类.show,Bird.info='鸟类'
Duck类.show,Duck.info='鸭子'

第一行里 cls 是 Duck，所以 cls.info 拿到的是子类的 "鸭子"，而 Bird.info 仍是 "鸟类"——cls 由调用者决定，这正是 super() 在类方法里的行为。

多继承与 Mixin

多继承的语法是 class 类名(父类1, 父类2, ...)，调用方法时先在子类里找，找不到再从左到右依次找父类。把不同能力拆成职责单一的类再组合进来，这种设计模式叫混入类（Mixin）：

class Flyable:
    """飞行能力类：使用此类的子类需要提供 name 属性"""

    def fly(self):
        print(f"{self.name} 正在飞行")


class Swimming:
    """游泳能力类：使用此类的子类需要提供 name 属性"""

    def swim(self):
        print(f"{self.name} 正在游泳")


class Bird:
    """鸟类基类"""

    def __init__(self, name):
        self.name = name

    def make_sound(self):
        print(f"{self.name} 在鸣叫")


class Duck(Bird, Flyable, Swimming):
    """鸭子类 - 继承鸟类和多种能力"""

    def __init__(self, name):
        super().__init__(name)

    def catch_fish(self):
        print(f"{self.name} 抓 fish")


duck = Duck("小黄鸭")
duck.fly()
duck.swim()
duck.make_sound()
duck.catch_fish()

小黄鸭 正在飞行
小黄鸭 正在游泳
小黄鸭 在鸣叫
小黄鸭 抓 fish

Flyable、Swimming 都是混入类：各自只提供一种能力，假设使用者提供 name 属性。混入类的特点是不单独实例化、一般不含 __init__、依赖关系靠约定或文档说明；好处是单一职责、可复用、可自由组合、结构清晰。

MRO

如果多个父类有同名方法，子类调用时按一个固定顺序查找，这个顺序就是方法解析顺序（Method Resolution Order，MRO）。MRO 是 Python 为多继承设计的方法/属性查找规则，本质是一个类的线性搜索列表，可以用 类名.__mro__ 或 类名.mro() 查看。

Python 3 的 MRO 遵循 C3 算法，要点是：

  1. 先找子类自己的方法；
  2. 再按父类定义的顺序从左到右查找；
  3. 最后找共同的祖先类。

C3 算法的三个关键性质：

  • 局部优先顺序：子类优先于父类，同一父类的多个子类保持声明顺序。下图图 1 是 D(B, C)，先 B 后 C；图 2 是 D(C, B)，先 C 后 B。
  • 一致性：如果 D 继承 B、B 继承 A，那么 MRO 中 D 必须在 B 之前、B 必须在 A 之前。
  • 单调性：子类的 MRO 不会破坏父类的 MRO 顺序。Python 2.2 之前用 DFS（深度优先搜索），图 1 会得到 DBAC，破坏「子类优先于父类」；自 Python 2.3 引入 C3 算法后得到 DBCA。

两种查找情形：

  • 沿着 MRO 找到方法就停止（show_one 命中 D，show_two 命中 D 后没有 super()，停在 D）；
  • 找到的方法里还有 super().方法() 就继续沿着 MRO 往下走，直到某一步没有 super() 为止（show_three、show_four 依次穿过 D、B、C、A）。

菱形继承

D 继承 B 和 C，B、C 又都继承自 A，就是菱形（钻石）结构：

没有 MRO 的 C3 算法时，调用 D 的方法可能让 A 的方法被 B 和 C ==各调用一次==，造成逻辑重复。C3 算法把共同基类 A 放在 MRO 列表的最后一个父类之后，保证它只被查找一次。

Note

多继承中 super() 查找的不是「当前类的父类」，而是 ==MRO 列表里的下一个类==。这是 super() 的核心逻辑，也是 MRO 能解决菱形继承的关键。super().show_three() 在 B 里执行时，找到的是 C 而不是 A。

避坑两条：

  1. 写了多继承就第一时间用 类名.mro() 看查找顺序，别凭直觉猜方法会走到谁；
  2. 尽量避免多继承中出现大量同名方法。多继承适合「复用不同父类的不同方法」，不适合用 MRO 去调和一堆同名冲突。

多继承的初始化：两种方案

ElectricCar 同时继承 Vehicle 和 Electronic，两个父类又都继承 Goods。

方式一：每个父类里用 父类名.__init__(self, ...) 直接点名，子类分别调用两个父类的构造方法。这样不会因为 super() 沿着 MRO 跑而漏掉或重复初始化。

class Goods:
    def __init__(self, goods_name, goods_price):
        self.goods_name = goods_name
        self.goods_price = goods_price


class Vehicle(Goods):
    def __init__(self, goods_name, goods_price, max_speed, seat_num):
        self.max_speed = max_speed
        self.seat_num = seat_num
        # super().__init__(goods_name, goods_price)  # 对 ElectricCar 来说，super() 会去找 Electronic
        Goods.__init__(self, goods_name, goods_price)

    def drive(self):
        print(f"最大速度{self.max_speed}km/h，{self.seat_num}座车辆正在行驶")


class Electronic(Goods):
    def __init__(self, goods_name, goods_price, battery_cap):
        self.battery_cap = battery_cap
        self.electric = 100
        Goods.__init__(self, goods_name, goods_price)

    def charge(self):
        self.electric = 100
        print(f"{self.battery_cap}kWh电池已充满，电量100%")


class ElectricCar(Vehicle, Electronic):
    def __init__(self, goods_name, goods_price, max_speed, seat_num, battery_cap, autopilot_level):
        Vehicle.__init__(self, goods_name, goods_price, max_speed, seat_num)
        Electronic.__init__(self, goods_name, goods_price, battery_cap)
        self.autopilot_level = autopilot_level

方式二：协作式 super().__init__(**params)——每个父类只处理自己的参数，剩下的用 **params 继续往 MRO 下一站传递，共同基类 Goods 的初始化只发生一次。

class Goods:
    def __init__(self, goods_name, goods_price, **params):

    def charge(self):
        self.electric = 100
        print(f"{self.battery_cap}kWh电池已充满，电量100%")

两种方式输出完全一致，区别在维护性：

父类名.__init__(self, ...)协作式 super().__init__(**params)
是否依赖 MRO不依赖，点名调用依赖，沿 MRO 依次传递
共同基类初始化次数每个父类各调一次（这里 Goods.__init__ 被调了两次）只调一次
新增父类时要在子类里再写一行通常不用改子类
可读性直观，但硬编码父类名需要理解 **params 的传递链

ElectricCar 的 MRO 是 ['ElectricCar', 'Vehicle', 'Electronic', 'Goods', 'object']，协作式写法正是沿着这条链一次走完。

多态与鸭子类型

多态的定义是：同一操作作用于不同的对象，产生不同的执行结果。

实现多态效果有两种方式。基于继承加方法重写，是 Java 这类语言的常规做法：

class Animal:
    def go(self):
        pass


class Dog(Animal):
    def go(self):
        print("小狗跑")


class Fish(Animal):
    def go(self):
        print("鱼儿游")


class Bird(Animal):
    def go(self):
        print("鸟儿飞")


def go(animal):
    animal.go()


dog = Dog()
fish = Fish()
bird = Bird()
go(dog)
go(fish)
go(bird)

鱼儿游
鸟儿飞

Python 作为动态类型语言，更常用的是鸭子类型：不需要继承，也不需要声明类型，只要对象有同名方法就能用：

class Dog:
    def go(self):
        print("小狗跑")


class Fish:
    def go(self):
        print("鱼儿游")


class Bird:
    def go(self):
        print("鸟儿飞")


class Car:
    def go(self):
        print("汽车开")


def go(animal):
    animal.go()


for obj in (Dog(), Fish(), Bird(), Car()):
    go(obj)

鱼儿游
鸟儿飞
汽车开

鸭子类型（Duck Typing）的精髓是一句话：==如果它走起来像鸭子，叫起来像鸭子，那么它就是鸭子==。翻译成编程术语：一个对象有没有用，不取决于它继承自哪个类，而取决于它有没有实现特定的方法或属性。

特性传统继承/接口（Java/C++ 风格）鸭子类型（Python 风格）
检查时机编译期（或代码编写期）运行时
关注点对象是什么（is-a）对象能做什么
代码耦合度较高，必须显式继承极低，只需实现同名方法
灵活性较差，改类型结构成本高极高，任何「会叫」的对象都能用

鸭子类型最典型的落地就是内置函数和魔法方法：len() 不要求参数是列表或元组，只要对象实现了 __len__()；for 不要求参数是列表，只要对象实现了 __iter__()（迭代器协议见 迭代器与生成器）。

class MyCollection:
    def __len__(self):
        return 100


print(len(MyCollection()))


class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        n = self.start
        while n > 0:
            yield n
            n -= 1


for i in Countdown(3):
    print(i)

Warning

鸭子类型的代价是错误只能在运行时暴露：方法名拼错、参数个数不对，都要等真正调用到那一行才报 AttributeError 或 TypeError。类型注解和 mypy 这类工具能在编写期补上这一层检查，见 类型注解与泛型。

抽象类

抽象类是包含抽象方法的类，它不能被直接实例化，子类继承后必须重写所有抽象方法。父类定义抽象方法的意义是约定「所有子类都必须提供某个方法」。

Python 里的抽象类要满足两个条件：

  1. 继承 abc.ABC；
  2. 抽象方法上加 @abc.abstractmethod 装饰器。
import abc


class Person(abc.ABC):
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @abc.abstractmethod
    def eat(self):
        pass

    def show(self):
        print(f"姓名：{self.name}，年龄：{self.age}")


class Student(Person):
    def eat(self):
        print("吃学生餐")


try:
    p = Person("张三", 23)
except TypeError as e:
    print("Person('张三', 23) ->", e)

p = Student("张三", 23)
p.show()
p.eat()
print(Student.__mro__)

案例：愤怒的小鸟

绿色小猪偷走了鸟蛋，小鸟们用各自的技能攻击小猪建造的障碍物。这个案例把前面几节的知识点串一遍。

类设计

类角色属性方法
Birds所有小鸟的基类，定义通用属性和行为name、color、skill_descriptionfly()、call()、use_skill()
RedBirds / YellowBirds / BlueBirds具体小鸟，继承 Birds，重写部分方法通过 super().__init__() 初始化三个属性重写 fly()、call()，继承 use_skill()
Obstacle障碍物，负责被攻击的逻辑name、strengthbe_attacked(bird)

设计意图：Birds 体现抽象与封装；三个子类各自重写 fly()、call() 体现继承与多态；Obstacle.be_attacked(bird) 接收任意小鸟对象，靠 isinstance 判断种类决定伤害，体现对象之间的交互。

核心代码

class Birds:
    def __init__(self, name, color, skill_description):
        self.name = name
        self.color = color
        self.skill_description = skill_description

    def fly(self):
        print(f"{self.name} 正在飞行...")

    def call(self):
        print(f"{self.name} 发出叫声...")

    def use_skill(self):
        print(f"{self.name} 使用了技能：{self.skill_description}")


class RedBirds(Birds):
    def __init__(self):
        super().__init__("红火", "红色", "撞击前方障碍物，造成大量伤害")

    def fly(self):
        print("红火以稳定的速度向前飞行...")

    def call(self):
        print("红火发出 'wei呀....' 的叫声")


class Obstacle:
    def __init__(self, name, strength):
        self.name = name
        self.strength = strength

    def be_attacked(self, bird):
        print(f"{bird.name} 冲向了 {self.name}")
        bird.use_skill()
        if isinstance(bird, RedBirds):
            damage = 80
        elif isinstance(bird, YellowBirds):
            damage = 50
        elif isinstance(bird, BlueBirds):
            damage = 30 * 3  # 分裂成三只，每只造成 30 点伤害
        self.strength -= damage
        if self.strength <= 0:
            print(f"{self.name} 被摧毁了！")
        else:
            print(f"{self.name} 还剩余 {self.strength} 点强度")
